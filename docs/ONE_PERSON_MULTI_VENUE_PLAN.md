# 一个人，多个场合：统一方案

> 问题：群里和私聊里，她会不会像变了个人？
> 答案：人格不会变，但**关系、记忆、以及“她对你的温度”目前都被场合切碎了**。
> 本方案把“人”和“场合”拆开：关系归人，脸归场合，记忆分两层，披露看受众。

---

## 一、诊断：三个把“一个人”切碎的地方

### 1.1 同一个人，两条关系档案

`social_bonds` 的主键是 `(chat_key, user_id)`。同一个人在你的群和私聊里是两行：

| | 群聊 | 私聊 |
|---|---|---|
| 好感 | 54.5 | 32.1 |
| 信任 | 0.61 | **0.78** |
| 关系深度 | **71.0** | 50.7 |
| 消息数 | 680 | 312 |

同一个你，群里“更亲近”，私聊“更信任但更不俏皮”。这不是人设分裂，是**一段关系被存成了两段**。

### 1.2 更深的根因：`bond_depth` 是“组内相对值”，不是绝对关系

代码事实：

- `bond_adapt.normalize_group`：把六个特征换成**组内百分位**（L1）；
- `bond_scoring._blend`：`0.5 × 校准深度 + 0.5 × 100 × 组内排名`（L2）。

所以 `bond_depth` 不是“你和她有多深”，而是“**你在这个群里排第几**”。

后果：

- 同一个你，在大群里排第 20 → depth 低；在私聊里只有你 → depth 高；
- `persona_stance.stance_vector` 直接用 `bond.bond_depth` 算温柔/耐心；
- `drives.compute_care_weight` 也用它算照护权重。

**也就是说：她对你的温柔，会因为你群里多了几个活跃的人而下降。** 这不是人格，是排名。

一个验证：用 `depth_from_stats` 从同一份统计重算，群里的绝对深度是 **92.05**，而存储的 `bond_depth` 是 **71.0**；私聊绝对深度 **51.33**，存储 **50.7**。
差值不是陈旧数据，是**相对化**造成的。

### 1.3 记忆与特质按场合分裂

- 事实、往事、规则按 `chat_key` 存：私聊说的事，群里想不起来；
- `persona_traits`：6 条全局 + 3 条只属于群；群里长出的习惯，私聊不一定有；
- 情绪/驱动是全局的：群里被气到，私聊带余温——这是“一个人”，但需要受众感来收。

## 二、设计原则

1. **关系归人**：信任、绝对深度、依恋是人对人的属性，不随房间变。
2. **脸归场合**：在哪个群、当着谁、用什么尺度开玩笑，是场合属性。
3. **记忆分两层**：关于“你这个人”的事实全局；关于“这个场合发生的事”本地。
4. **披露看受众**：来源、归属、敏感度、谁知道，决定说/暗示/保留。
5. **派生值可重建**：`bond_depth` 这类值要么实时算，要么存储必须可重建、可解释。
6. **不拍数**：合并公式、饱和常数、信任聚合都要有数据与区间。

## 三、目标模型：四层

```
┌─ 人（person）─────────────────────────────────────────────┐
│ persons(person_id)                                       │
│ person_bonds: trust, trust_pos/neg, depth_absolute,      │
│               attachment, is_rival                       │
└──────────────────────────────────────────────────────────┘
┌─ 场合（venue）───────────────────────────────────────────┐
│ bond_venues: affinity, familiarity, role, norms,         │
│              venue_rank（组内排名，仅用于场面）           │
└──────────────────────────────────────────────────────────┘
┌─ 记忆（memory）──────────────────────────────────────────┐
│ person_facts：关于这个人的事实（全局，带来源）            │
│ venue_events：这个场合发生的事（本地，带参与者）           │
│ knowledge_state：谁知道什么                               │
└──────────────────────────────────────────────────────────┘
┌─ 披露（disclosure）──────────────────────────────────────┐
│ 硬门：private/secret 的受众准入                          │
│ 人格选择：public/group 说/暗示/保留                       │
│ disclosures：她说过什么、在哪、对谁、为什么               │
└──────────────────────────────────────────────────────────┘
```

## 四、关系合并算法

### 4.1 信任：人对人，证据加权

现状只有每群的 `trust_score`。迁移时：

- 若保留正负证据（推荐）：`trust = pos / (pos + neg)`，跨群累加；
- 若只有分数：按互动量加权平均，并转成伪计数：
  `pos = trust × k`，`neg = (1−trust) × k`，`k` 为约定（如 10），写入台账。

你的数据：`0.61×680 + 0.78×312` 加权 ≈ **0.663**。不是 0.61，也不是 0.78。

### 4.2 绝对深度：跨场合重算，并重拟合饱和

不要平均两段 depth，也不要直接相加特征——`FREQ_SATURATION=452` 是按**单群** P95 定的，跨群相加会把深度推到 92+。

做法：

1. 按 `person_id` 汇总 `bond_depth_stats`（msgs/sessions/impact/betrayals 等）；
2. 在**人级分布**上重拟合 `FREQ_SATURATION`/`DIVERSITY_SATURATION`/`IMPACT_SATURATION`（P95，记 n 与 CI，走 E1 台账）；
3. 用新常数算 `depth_absolute`；
4. 先 dry-run：对比旧 per-venue depth 与新 absolute 的分布、排序相关性（Spearman），确认没有大面积跳变。

你的数据：群 368 条 + 私聊 28 条 = 396 条；按旧常数直接算，绝对深度 92.54，明显高于存储 71.0——**必须重拟合**，否则所有人都会“突然变亲近”。

### 4.3 好感：场合的脸，不是关系的核心

`affinity` 留在 `bond_venues`：它表达“在这个场合，她和你多放得开”。

- 群里 54.5（爱开玩笑）合理；
- 私聊 32.1（更认真/更收敛）也合理；
- 它们**不再是同一段关系的两个版本**，而是同一段关系的两种表现。

### 4.4 立场映射：哪些该一样，哪些可以不一样

| 立场分量 | 来源 | 跨场合 |
|---|---|---|
| 温柔 | 人级 `trust` + `depth_absolute` | **应一致** |
| 耐心 | 人级 `trust` | **应一致** |
| 俏皮 | 场合 `affinity` | **可以不同**（群聊更闹，私聊更静） |
| 组内排名 | `venue_rank` | 仅用于场面/展示，**不参与温度** |

这就是“同一个人，不同脸”：温度不随房间变，玩笑尺度可以。

## 五、记忆分层与披露

### 5.1 两层记忆

- **person_facts**：关于你的事实（名字、喜好、说过的重要事、关系边界）——全局，任何场合可召回；
- **venue_events**：这个群/私聊发生的事——本地，带参与者与来源；
- 全局事实（新闻、梗）单独标 `scope=global`。

### 5.2 每条记忆带四样东西

| 字段 | 作用 |
|---|---|
| `source`（人/场合/时间/原话） | 她知道“从哪听来的” |
| `owner`（这是谁的信息） | 决定谁能听 |
| `sensitivity`（public/group/private/secret） | 决定硬门 |
| `audience`（记录时在场的人） | 决定受众边界 |

### 5.3 谁知道什么

`knowledge_state(memory_id, person_id, state)`：她说的、别人说的、听来的、推断的。
这是“告知史”，也是防止重复讲给同一个人的依据。

### 5.4 披露决策

```
候选记忆 → 硬门（private/secret）→ 受众感 → 人格选择 → 说/暗示/保留/问/转移
```

- 硬门只拦 private/secret 与第三方秘密；
- public/group 交给 7 维：温柔保护、狡黠暗示、占有欲保留、叛逆破规矩、自信直说、傲娇否认、俏皮当笑话；
- 所有选择写 `disclosures`，结果回流现有塑性/关系。

## 六、每轮提示词结构

```
system：身份 + 认知层级 + 表情包 + 语音指南
user：
  【场合】场景/时间/在场的人/这里的规矩
  【你和他】人级关系（信任/深度）+ 你知道他什么 + 他知道什么
  【记忆】person_facts（全局）+ venue_events（本地，经披露过滤）
  【此刻】情绪/驱动/快状态
  【性格】7 维 rubric + 依恋 + 腔调
  【待处理】最新消息
```

关键：关系只出现一次（人级），场合只描述“这里怎么说话”，不再出现两套互相矛盾的关系数字。

## 七、一致性规则与评测

### 7.1 一致性规则（可自动测）

对同一个 `person_id`，在群/私聊分别渲染：

- 温柔、耐心、叛逆的差异 **≤ 2 分**（只允许 play 通过系数间接影响）；
- 俏皮允许差异，但必须由 `bond_venues.affinity` 解释；
- 信任、深度、依恋的值 **完全相同**。

### 7.2 评测

1. **关系一致性**：同一人跨场合的 trust/depth 相同；温度差 ≤2；俏皮差可由 affinity 解释；
2. **记忆连贯**：person_facts 跨场合可召回；venue_events 不越界；
3. **披露授权**：private/secret 不进入未授权受众（0 违规）；
4. **多人记忆**：GroupMemBench 风格（谁说的/关于谁/谁知道/知识更新）；
5. **告知史**：同一件事不重复讲给同一个人。

## 八、迁移步骤（直接上，可回滚）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 深度拆分** | 新增 `depth_absolute`（人级）与 `venue_rank`（场合）；stance/care 改用 absolute；保留旧字段做对照 | 同一人跨场合温度差 ≤2；深度排序 Spearman ≥0.95 |
| **P1 人级关系** | `persons`/`person_bonds`/`bond_venues`；trust 聚合；depth 重拟合饱和；dry-run 后迁移 | 分布无大面积跳变；无“突然变亲近” |
| **P2 记忆分层** | `scope` + `source`/`owner`/`sensitivity`/`audience`；person facts vs venue events | 私聊事实不在群里被直接引用 |
| **P3 告知史+硬门** | `knowledge_state`、`disclosures`、`private/secret` 准入 | secret 泄露 0；private 默认保留 |
| **P4 人格分寸** | public/group 的 say/hint/keep 接 7 维 | 盲评能分辨“暗示 vs 直说” |
| **P5 评测** | 一致性 + 授权 + GroupMemBench 子集 | 全套通过 |

每阶段配 `ECHOMIND_*` 开关，出问题可回退；**不做影子**，但每一步都有 dry-run 的数据对照。

## 九、风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 深度重拟合导致“突然亲近” | 旧常数按单群 P95 | 人级重拟合 + dry-run + 排序对照 |
| 信任聚合改变态度 | 0.61/0.78 → 0.663 | 先只读对照，再切换 |
| 把“相对深度”当 bug 修掉 | 它是有意的组内排名 | 拆字段，不覆盖原字段 |
| person_facts 误判 | 名字/话题混淆 | subject→person 只在高置信时迁移 |
| 私聊事实进群 | 记忆全局化 | 硬门 + 来源/受众 |
| 特质仍按场合 | 群习惯不带入私聊 | 默认全局，除非显式“只在这个群” |
| 提示词变长 | 多一个“你和他”块 | 控制字数，关系只出现一次 |

## 十一、下一步

**先做 P0（深度拆分）**，因为它不改表结构就能验证“温度不再随房间变”：

1. 新增 `depth_absolute`（人级，先用现有常数，标注待重拟合）与 `venue_rank`；
2. stance/care 改用 `depth_absolute`；
3. 用你的数据跑一致性：群 vs 私聊，温柔/耐心差应 ≤2；
4. 再做 P1 的表迁移与饱和重拟合。

这样你能先看到“她还是同一个人”，再决定要不要继续上记忆/披露层。
