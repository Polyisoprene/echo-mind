# D15 检索基线（关键词 vs 同义改写）

## 方法

`scripts/eval_memory_retrieval.py`：

- 30 条事实（10 条目标 + 20 条干扰）；
- 10 条查询，刻意用与目标事实**几乎不重叠**的措辞（如“工作”对“岗位”、“睡”对“熬夜”）；
- 调 `select_relevant_facts(..., limit=5)`，统计目标是否进 top-5。

## 结果（2026-10-31）

```
recall@5 = 5/10 = 0.50
```

| 查询 | 结果 |
|---|---|
| 家里那只小东西最近胃口不好 | ✅ |
| 那份工作还顺利吗 | ✅ |
| 你昨晚几点睡的 | ✅ |
| 假期想出门走走吗 | ✅ |
| 她平时喝什么咖啡 | ✅ |
| 材料什么时候要交 | ❌ |
| L 最近身体怎么样 | ❌ |
| 那部片子看完哭了吗 | ❌ |
| 天气不好会害怕吗 | ❌ |
| 这个月钱够花吗 | ❌ |

## Bigram-IDF 对照（2026-10-31）

同一批数据上，字符 bigram + IDF 的 recall@5 也是 **0.50**，漏掉的是同样 5 条：

```
bigram-idf recall@5 = 5/10 = 0.50
```

说明缺口不是分词粒度，而是**缺少语义表示**；继续在字面/ngram 上加权不会解决“工作 vs 岗位”“睡 vs 熬夜”这类同义。

## 需要的决策

D15 语义检索必须选一个 embedding 后端：

| 方案 | 代价 | 风险 |
|---|---|---|
| 本地小模型（如 bge-small-zh） | 依赖、下载、内存 | 需要新依赖与模型分发 |
| API embeddings | 每次写入/检索的费用与延迟 | 记忆内容出本机，隐私 |
| 暂不接，保留关键词 | 0 | 同义改写召回继续 0.5 |

在选定前不引入依赖，也不改线上检索。

## 解读与限制

- 0.5 是**乐观上界**：中文 tokenizer 仍可能命中单字（“猫”“工作”“睡”），并非真正语义；
- 纯改写、零字面重叠时召回更低；
- 合成数据，不等于真实会话分布；
- 结论：关键词/关系加权不足以覆盖同义改写，需要 hybrid 语义检索（D15 设计 B）。
